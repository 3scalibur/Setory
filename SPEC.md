# ТЗ: фітнес-апка — логіка (промпт для Claude Code)

Створено 3 жовтня 2026, оновлено 14 жовтня 2026. Цей файл — головна версія ТЗ; зміни вносяться сюди. Технічні рішення етапу 1 — у `docs/ARCHITECTURE.md`.

## 1. Контекст для Claude Code

Ти — senior mobile-розробник. Будуємо персональний трекер силових тренувань у дусі Hevy: каталог вправ з технікою, логування підходів (вага × повтори), підстановка минулих результатів, коронки за рекорди.

Проблема, яку вирішуємо: користувач тренується після роботи і часто має лише \~60 хвилин. Він не встигає закрити всі вправи дня програми, і пропущені м'язи просто забуваються. У Hevy він не може швидко запустити одну вправу без повної програми, і прогрес не єдиний між різними способами запуску.

Що робимо зараз:

- Тільки модель даних і бізнес-логіку. UI — мінімальний технічний, дизайн робимо пізніше окремими кроками.
- Не вигадуй функцій поза цим ТЗ. Якщо правило неоднозначне — спитай до реалізації, а не після.
- Мова інтерфейсу — українська, назви в коді — англійською.

## 2. Головний принцип: прогрес належить вправі, а не програмі

Уся історія зберігається як плаский журнал підходів, прив'язаних до `exercise_id`. Програма — це лише шаблон «що зробити», вона ніколи не володіє результатами.

З цього випливають правила, які не можна порушувати:

1. Будь-який запит «що я робив минулого разу», «який мій рекорд», «коли я тренував цей м'яз» фільтрує підходи за `exercise_id` (або групою м'язів) по всіх сесіях, незалежно від джерела запуску.
2. Режим запуску (програма, окрема вправа, день пропущених) — лише метадані сесії. Він не впливає на те, чи зарахується підхід у прогрес.
3. Рекорди і список пропущених вправ — похідні дані, обчислені з журналу. Якщо кешуєш їх для швидкості, кеш повинен повністю перебудовуватись з журналу однією функцією.
4. Редагування або видалення програми не змінює і не видаляє історію. Редагування минулої сесії автоматично перераховує рекорди і список пропущених.

## 3. Стек і архітектура

Рекомендований стек: Expo (React Native) + TypeScript + SQLite (`expo-sqlite`) + Drizzle ORM. Якщо бачиш кращу альтернативу — запропонуй і поясни чому, але не змінюй без підтвердження.

- **Local-first, повністю офлайн.** У залі часто немає зв'язку. Сервер і синхронізація — не зараз, але схема має їх допускати: UUID як ключі, `created_at`/`updated_at` у всіх таблицях, м'яке видалення (`deleted_at`).
- **Доменний шар окремо від UI і БД.** Уся логіка (prefill, рекорди, backlog, генерація дня) — чисті функції в `src/domain/`, які приймають дані і повертають результат без побічних ефектів. Робота з БД — у `src/data/` (репозиторії).
- **Тести обов'язкові.** Кожна доменна функція покрита юніт-тестами (Jest), щонайменше сценарії з розділу 12. Логіка вважається готовою, коли тести зелені, а не коли «на екрані наче працює».
- **Одиниці:** вага зберігається в кг (decimal), час — UTC timestamp, тривалість — секунди.

## 4. Модель даних

Чотири групи сутностей: каталог вправ, шаблони програм, журнал тренувань, налаштування. Назви полів — орієнтир, типи та індекси підбери сам.

```ts
// ---------- Каталог ----------
type ExerciseType =
  | 'weight_reps'          // жим штанги: вага × повтори
  | 'bodyweight_reps'      // віджимання: тільки повтори
  | 'weighted_bodyweight'  // підтягування з обтяженням: +вага × повтори
  | 'assisted_bodyweight'  // гравітрон: допомога × повтори (менше = краще)
  | 'duration'             // планка: секунди
  | 'distance_duration';   // кардіо: метри + секунди

type MuscleGroup =
  | 'chest' | 'lats' | 'upper_back' | 'lower_back' | 'traps' | 'neck'
  | 'front_delts' | 'side_delts' | 'rear_delts'
  | 'biceps' | 'triceps' | 'forearms' | 'abs'
  | 'quads' | 'hamstrings' | 'glutes' | 'calves' | 'adductors' | 'abductors';

interface Exercise {
  id: string;
  name: string;                 // основна назва (укр)
  aliases: string[];            // для пошуку: рос/англ/сленг («жим лежа», «bench press»)
  primaryMuscles: MuscleGroup[];
  secondaryMuscles: MuscleGroup[];
  equipment: 'barbell' | 'dumbbell' | 'machine' | 'cable' | 'bodyweight' | 'kettlebell' | 'band' | 'other';
  type: ExerciseType;
  mechanic: 'compound' | 'isolation';
  instructions?: string;        // текст техніки
  mediaUrl?: string;            // gif/відео/фото техніки
  isCustom: boolean;
  archivedAt?: number;          // не видаляємо, якщо є історія
}

// ---------- Шаблони: папки і програми (розділ 10б) ----------
// UI: «Папка» = Program, «Програма» в папці = ProgramDay
interface Program {                     // папка
  id: string; name: string; order: number;
  isActive: boolean;                    // активна лише одна: з неї «Наступне: Push»
}
interface ProgramDay {                  // програма в папці (Push / Pull / Legs)
  id: string; programId: string; name: string; order: number; note?: string;
}
interface ProgramDayExercise {          // «слот» вправи в програмі
  id: string; programDayId: string; exerciseId: string; order: number;
  restSec: number; note?: string;
}
interface ProgramDaySet {               // кожен підхід — окремий рядок, як у Hevy
  id: string; programDayExerciseId: string; index: number;
  kind: 'warmup' | 'working' | 'drop' | 'failure';
  weightKg?: number;                    // стартова вага: лише поки вправу ще не виконували
  repsMin?: number; repsMax?: number;   // 8 → min = max = 8; діапазон 8–10
  durationSec?: number; distanceM?: number;
}

// ---------- Журнал (єдине джерело правди) ----------
interface WorkoutSession {
  id: string;
  source: 'program_day' | 'single_exercise' | 'catch_up' | 'free';
  programId?: string; programDayId?: string;   // лише для program_day
  status: 'active' | 'finished' | 'discarded';
  startedAt: number; finishedAt?: number; note?: string;
}
interface SessionExercise {
  id: string; sessionId: string; exerciseId: string; order: number;
  programDayExerciseId?: string;  // який слот програми це виконує (якщо є)
  skipped?: boolean;              // слот прибрали з сесії без виконання
  targetsSnapshot?: TargetSet[];  // ЗНІМОК рядків ProgramDaySet на момент старту
  restSec?: number;
}
type TargetSet = Pick<ProgramDaySet, 'index' | 'kind' | 'weightKg' | 'repsMin' | 'repsMax' | 'durationSec' | 'distanceM'>;
interface SetEntry {
  id: string; sessionExerciseId: string; index: number;
  kind: 'warmup' | 'working' | 'drop' | 'failure';
  weightKg?: number; reps?: number; durationSec?: number; distanceM?: number; rpe?: number;
  completed: boolean; completedAt?: number;
}

// ---------- Службове ----------
interface BacklogDismissal { id: string; exerciseId: string; dismissedAt: number } // «прибрати з пропущених»
interface Settings { key: string; value: string }
```

Визначення, які використовуються далі:

- **Робочий підхід** = `completed === true` і `kind !== 'warmup'`. Розминка не йде в рекорди і не «закриває» вправу.
- **Вправу виконано в сесії** = у ній є щонайменше `DONE_THRESHOLD` робочих підходів (за замовчуванням 1; одна константа в налаштуваннях).
- **Рахуються лише сесії** зі `status === 'finished'` (активна сесія — лише для PR у реальному часі, див. розділ 7).
- **Наступний день програми** не зберігається, а обчислюється: день після останньої завершеної `program_day`-сесії цієї програми (по колу). Сесії `single_exercise`, `catch_up`, `free` цей покажчик не зсувають.

## 5. Режими запуску тренування

Є чотири способи почати сесію, але всередині вони працюють однаково. Одночасно активна лише одна сесія.

1. **День програми (`program_day`).** Користувач обирає день (за замовчуванням запропоновано наступний по колу). Для кожного слоту створюється `SessionExercise` зі знімком цілей і підставленими підходами (розділ 6).
2. **Окрема вправа (`single_exercise`).** Знайшов вправу в пошуку, у картці вправи, у списку пропущених або в перегляді дня програми → натиснув «Виконати» → сесія з однією вправою, вже з підставленими минулими цифрами. Це має займати максимум 2 тапи після пошуку. Якщо вже є активна сесія — вправа додається в неї, нова не створюється.
3. **День пропущених (`catch_up`).** Апка пропонує набір вправ з backlog (розділ 9), користувач редагує список і стартує. Цілі (підходи/повтори) беруться зі слоту, який був пропущений.
4. **Вільне тренування (`free`).** Порожня сесія, вправи додаються по ходу.

У будь-якій активній сесії можна: додати вправу через пошук, прибрати, змінити порядок, додати/видалити підхід, замінити вправу на іншу.

Правила для вправ-слотів у `program_day`:

- **Прибрати** вправу-слот не видаляє рядок, а ставить `skipped: true`. На екрані її немає, але вона лишається як «заплановано і не зроблено» — це потрібно для backlog.
- **Замінити** вправу-слот на альтернативу (наприклад, тренажер зайнятий) зберігає `programDayExerciseId`. Якщо альтернативу виконано, слот вважається закритим. Історія і рекорди пишуться на альтернативну вправу.

Завершення сесії:

- **«Завершити»** → `status: 'finished'`. Невиконані підходи видаляються. Вправи без жодного робочого підходу видаляються, крім вправ-слотів — вони лишаються для backlog.
- **«Скасувати»** → `status: 'discarded'`, сесія ігнорується всюди.
- Джерело запуску не змінюється, навіть якщо в `single_exercise` додали ще 5 вправ: це лише метадані.

## 6. Підстановка минулих результатів (prefill)

Коли вправа з'являється в сесії будь-яким способом, її підходи заповнюються з останнього виконання цієї вправи, незалежно від того, де її виконували. Функція: `buildPrefill(exerciseId, history, target?)`.

1. **Останнє виконання** = найсвіжіша завершена сесія будь-якого джерела, де ця вправа має хоча б один робочий підхід. Поточна сесія не враховується.
2. **Кількість робочих підходів:** як минулого разу (зробив 4×8 окремо — у програмі теж буде 4). Немає історії → `targetSets` зі слоту. Немає і слоту → 3. Джерело кількості перемикається в налаштуваннях (`last` | `template`).
3. **Вага і повтори** підходу i = робочий підхід i з останнього виконання. Якщо підходів тепер більше — копіюється останній робочий. Немає історії → кг і повтори з рядка програми (розділ 10б); якщо в програмі їх немає — вага порожня, повтори = `targetRepsMin`.
4. **Розминочні підходи** копіюються як були минулого разу, з позначкою `warmup`.
5. **Підставлені підходи не виконані.** Користувач редагує цифри і ставить галочку — лише тоді `completed: true`.

Що бачить користувач біля кожної вправи:

- Стовпець **«Попереднє»** для кожного підходу (наприклад, «60 × 8»), як у Hevy. Тап — скопіювати в поля.
- Рядок **«Минулого разу»**: дата + звідки («12 вер, окремо» / «12 вер, Push» / «12 вер, день пропущених»).
- Якщо є слот — підказка **цілі** «ціль: 3 × 8–10».

Етап 2 (не зараз): підказка прогресії. Якщо минулого разу всі робочі підходи досягли `targetRepsMax`, показати «спробуй +2.5 кг» (крок — з налаштувань). Цифри в полях не міняти автоматично.

## 7. Рекорди і коронки

Коронка дається підходу в момент, коли його позначили виконаним, якщо він строго кращий за все, що було до нього по цій вправі — з будь-якого режиму запуску. Типи рекордів залежать від типу вправи:

| Тип вправи | Рекорди |
| --- | --- |
| `weight_reps` | найбільша вага; найбільше повторів з цією або більшою вагою; розрахунковий 1ПМ; об'єм підходу (вага × повтори) |
| `weighted_bodyweight` | те саме, вага = додаткове обтяження |
| `bodyweight_reps` | найбільше повторів за підхід |
| `assisted_bodyweight` | найменша допомога; найбільше повторів з цією або меншою допомогою |
| `duration` | найдовший час |
| `distance_duration` | найбільша дистанція |

Розрахунковий 1ПМ — формула Еплі, лише для підходів до 12 повторів:

```latex
1RM = w \times \left(1 + \frac{r}{30}\right)
```

Правила:

- Порівнюємо з робочими підходами завершених сесій + раніше виконаними підходами поточної сесії. Другий підхід, який б'є щойно поставлений рекорд, теж отримує коронку.
- Рівний результат — не рекорд. Перше в житті виконання вправи — база, без коронки.
- Розминка не рахується; `drop` і `failure` рахуються.
- Один підхід може бити кілька рекордів — одна коронка, при тапі список типів.
- Зняли галочку або змінили цифри → коронки в сесії перераховуються.
- Після завершення — підсумок сесії зі списком нових рекордів.
- У історії коронки показуються на підходах, які були рекордом на свій момент — це хронологічний прогін по журналу.

Функції: `evaluateSetPRs(set, priorSets, exerciseType)` і `rebuildPRs(exerciseId)`. Редагування чи видалення минулої сесії викликає `rebuildPRs` для всіх вправ цієї сесії.

## 8. Пропущені вправи (backlog)

Backlog не зберігається як окремий стан, а обчислюється з журналу функцією `computeBacklog(history, dismissals, now, settings)`. Зберігаються лише ручні «прибрати» (`BacklogDismissal`). Так список завжди узгоджений з історією, навіть після редагування чи видалення сесій.

Алгоритм:

1. **Пропуск.** У завершеній `program_day`-сесії є вправа-слот (`programDayExerciseId` заданий), яка не виконана: `skipped` або менше `DONE_THRESHOLD` робочих підходів. Подія = { exerciseId, missedAt = finishedAt сесії, назва дня, знімок цілей }.
2. **Закриття.** Подія закрита, якщо після `missedAt` є завершена сесія БУДЬ-ЯКОГО джерела, де цю `exerciseId` виконано. Окрема вправа, день пропущених, інший день програми — немає різниці.
3. **Злиття.** Відкриті події групуються за `exerciseId` в один елемент: `firstMissedAt`, `lastMissedAt`, `missCount`, цілі з найсвіжішої події. Пропустив біцепс два тижні поспіль — це одна вправа в списку з позначкою «×2», а не дві.
4. **Прибрані вручну.** Елемент прихований, якщо є `BacklogDismissal` цієї вправи з `dismissedAt ≥ lastMissedAt`. Новий пропуск після цього — вправа з'являється знову.
5. **Застарілі.** Елемент прихований, якщо `lastMissedAt` старший за `BACKLOG_EXPIRY_DAYS` (за замовчуванням 14). Архівні вправи не показуються.

Що не є пропуском: невиконані вправи в `single_exercise`, `catch_up` і `free` (там немає плану) та цілком пропущені дні — програма йде по колу, а не по календарю.

У списку пропущених кожна вправа показує: назву, основні м'язи, «пропущено ×2, останній раз 3 дні тому (Push)», кнопки «Виконати» і «Прибрати». На головному екрані — лічильник пропущених.

## 9. День пропущених і режим «маю N хвилин»

Апка сама збирає тренування з пропущених вправ під заданий час (за замовчуванням 60 хв). Функція: `suggestCatchUp(backlog, history, catalog, { timeBudgetMin, now }, settings)`. Результат — пропозиція, яку користувач редагує перед стартом. Функція детермінована: однаковий вхід → однаковий вихід.

**Оцінка часу вправи** = підходи × (час підходу + відпочинок) + підготовка.

- За замовчуванням: підхід 40 с, відпочинок зі слоту (або 150 с для `compound`, 90 с для `isolation`), підготовка 60 с.
- Якщо є історія — медіана інтервалу між `completedAt` сусідніх підходів цієї вправи замість «підхід + відпочинок». Так оцінка підлаштовується під реальний темп.

**Пріоритет** (сортування за спаданням, ваги — константи в налаштуваннях):

1. Скільки днів не тренувався найбільш занедбаний основний м'яз вправи (будь-яка вправа на цей м'яз зараховується).
2. `missCount` — скільки разів пропущено.
3. `firstMissedAt` — старіші пропуски вище.
4. Штраф: якщо основний м'яз тренувався менше ніж 48 год тому, вправа йде в кінець черги (не викидається).

**Заповнення:** жадібно по пріоритету, поки вміщається в бюджет часу. Якщо чергова не вміщається — пробуємо наступні, коротші. Не більше `MAX_PER_MUSCLE` (2) вправ на один основний м'яз.

**Порядок у сесії:** спочатку базові (`compound`), потім ізоляція; всередині — від великих м'язів до малих (фіксований список: ноги → спина → груди → плечі → руки → прес/ікри/шия).

**Екран пропозиції:** список вправ з оцінкою хвилин і сумою, можна прибрати, додати з backlog, переставити, змінити бюджет — і «Почати». Backlog порожній → пишемо «пропущених немає» і пропонуємо наступний день програми.

**Коли пропонувати:** на головному екрані поруч із «Наступне: Push», коли в backlog ≥ `CATCHUP_MIN_ITEMS` (4) вправ: «День пропущених, \~55 хв».

### Режим «маю N хвилин» для дня програми

Перед стартом `program_day` можна вказати час. Якщо оцінка дня більша за бюджет, апка відразу показує, що вміщається, а що ні: базові вправи і ті, що вже є в backlog, — вище. Те, що не вмістилось, позначається «не встигну» і після завершення автоматично потрапляє в backlog за звичайним правилом. Якщо час лишається — запропонувати додати 1–2 вправи з backlog.

## 10. Каталог, пошук і власні вправи

Пошук — головний вхід до окремої вправи, тому він має знаходити вправу з будь-якого природного формулювання.

**Пошук:**

- Шукає по `name` + `aliases`, укр/рос/англ: «жим лежачи», «жим лежа», «bench» — одна вправа.
- Нормалізація: нижній регістр, без апострофів (' ʼ ’), ё→е, зайві пробіли. Толерантність до одруків (наприклад, Fuse.js).
- Ранжування: початок слова > містить > нечіткий збіг; при рівності — ті, що робив нещодавно і частіше.
- Порожній запит → недавні вправи з історії. Фільтри: група м'язів, обладнання.
- У кожному рядку результату — кнопка «Виконати» (або «Додати», якщо є активна сесія).

**Картка вправи:** техніка (медіа + текст), м'язи, поточні рекорди, історія всіх виконань з позначкою джерела (окремо / день програми / день пропущених), кнопка «Виконати».

**Власні вправи:**

- Поля: назва (обов'язково), тип, основні/допоміжні м'язи, обладнання, `compound`/`isolation`; опційно — текст техніки, фото з галереї або посилання на відео, синоніми для пошуку.
- При створенні попередити, якщо є дуже схожа назва (щоб не роздвоювати історію).
- Тип вправи не можна змінити, якщо вже є історія. Видалення вправи з історією = архівація.

**Наповнення каталогу:** для MVP — 50–80 базових вправ з українськими назвами, синонімами і м'язами у seed-файлі, медіа пізніше. Для розширення розглянути відкриті бази вправ з зображеннями (наприклад, free-exercise-db чи wger) — перед використанням перевірити ліцензію медіа.

## 10б. Вкладка «Тренування»: папки, програми, позначки прогресу

Додано 7 жовтня. **Терміни:** у UI «Папка» = `Program` у коді, «Програма» всередині папки = `ProgramDay` (Push / Pull / Legs). Назви в коді не міняємо, щоб решта ТЗ лишалась узгодженою.

### Вкладка «Тренування»

- Зверху: «Почати порожнє тренування» (`free`), пошук вправ (розділ 10), «Наступне: Push» з активної папки і лічильник пропущених (розділи 8–9).
- Нижче — папки, кожну можна згорнути. У папці — програми в порядку `order`; у кожній: назва, вправи одним рядком, кнопка «Почати».
- Кнопки «Нова програма» і «Нова папка».

### Папки

- Створити, перейменувати, змінити порядок, видалити. Видалення папки з програмами — з підтвердженням (або спершу перенести програми). Історія, рекорди і prefill не змінюються (розділ 2, правило 4).
- На першому запуску створюється папка «Мої програми» — кожна програма завжди лежить у якійсь папці.
- Активна папка одна: з неї рахується «Наступне» по колу (`nextProgramDay`). Запустити будь-яку програму з будь-якої папки можна завжди; покажчик «Наступне» рахується окремо для кожної папки.

### Конструктор програми

- Назва → додати вправи через пошук (можна обрати кілька за раз) → задати підходи для кожної.
- **Кожен підхід — окремий рядок:** тип (розминка / робочий / дроп / до відмови), кг, повтори — число або діапазон (8–10). Колонки залежать від `ExerciseType`: без ваги для `bodyweight_reps`, «допомога» для `assisted_bodyweight`, час для `duration`.
- «+ Підхід» копіює останній рядок; будь-який рядок можна видалити.
- На вправу: відпочинок (за замовчуванням 150 с для `compound`, 90 с для `isolation`) і нотатка. Біля вправи — «Минулого разу: 60 × 8» з журналу, щоб ставити реальну вагу.
- Змінити порядок вправ, замінити, видалити; дублювати програму; перенести в іншу папку.
- Зберегти можна, коли є назва, хоча б одна вправа і в кожної хоча б один підхід.

### Кг: система пам'ятає минулий раз

- Програма не фіксує кг. На кожному тренуванні вводиш ту вагу, яку хочеш: поля завжди редагуються.
- Система запам'ятовує кг і повтори кожного підходу з останнього виконання цієї вправи, де б її не робили: у програмі, окремо чи в день пропущених.
- **У тренуванні** поля підходів уже заповнені цими цифрами (розділ 6). Стовпець «Минулого разу» показує їх і після того, як ти ввів нові, щоб було видно, з чим порівнювати.
- **У програмі** (вкладка «Тренування», картка програми, конструктор) біля кожного підходу показується кг з минулого разу. Після кожного тренування це оновлюється само, редагувати програму руками не треба.
- Підхід i бере цифри з робочого підходу i минулого разу. Якщо в програмі підходів більше, копіюється останній робочий.
- Кг з конструктора (`weightKg`) лише стартові: вони використовуються, поки вправу ще жодного разу не виконували.
- Повтори в програмі (8 або 8–10) лишаються ціллю: «ціль: 3 × 8–10».
- Кг з минулого разу **не записуються** в програму, а щоразу читаються з журналу функцією `lastPerformance(exerciseId)`. Так не виникає двох копій однієї цифри, які можуть розійтися (розділ 2).
- Де в розділах 5–9 згадано `targetSets` / `targetRepsMin` / `targetRepsMax`: це кількість робочих рядків `ProgramDaySet` і `repsMin` / `repsMax` відповідного рядка. Знімок цілей у сесії — копія рядків програми на момент старту (`targetsSnapshot`).

### Позначки прогресу

Дві позначки. Обидві з'являються в момент, коли підхід позначено виконаним, і перераховуються, якщо змінили цифри або зняли галочку:

- 🏆 **Рекорд** — краще, ніж будь-коли по цій вправі (розділ 7, без змін).
- ↑ **Прогрес** — підхід кращий за свій «Попереднє»: робочий підхід з тим самим номером в останньому виконанні цієї вправи (будь-який режим запуску).

Правило ↑: жоден показник не гірший і хоча б один кращий.

| Тип вправи | ↑, якщо |
| --- | --- |
| `weight_reps`, `weighted_bodyweight` | вага більша і повтори ≥, або вага та сама і повторів більше |
| `bodyweight_reps` | повторів більше |
| `assisted_bodyweight` | допомога менша і повтори ≥, або допомога та сама і повторів більше |
| `duration` | час довший |
| `distance_duration` | дистанція більша за час не довший, або та сама дистанція швидше |

- Більша вага з меншою кількістю повторів (62.5 × 6 після 60 × 8) — не ↑; рекорд 🏆 за вагою при цьому можливий.
- Розминка не порівнюється. Якщо попереднього підходу з таким номером немає (сьогодні 5 підходів, минулого разу 4) або вправа робиться вперше — позначки немає.
- Гірше або так само — нічого не показуємо.
- Якщо підхід дає і 🏆, і ↑ — показуємо лише 🏆.
- Підсумок тренування: «Рекорди: N · Прогрес у M вправах» (вправа з прогресом = хоча б один ↑ або 🏆).
- В історії ↑ показується так само — порівняння з попереднім виконанням на той момент.
- Функція: `compareWithPrevious(set, previousSet, exerciseType): 'up' | null` — чиста, з тестами (розділ 12, сценарії 20–21).

## 11. Крайні випадки

- **Апка закрилась / сів телефон посеред тренування.** Кожна зміна підходу одразу пишеться в БД. При запуску, якщо є активна сесія — «Продовжити / Завершити / Скасувати». Активна сесія старша за 6 год → запропонувати завершити з `finishedAt` = час останнього виконаного підходу.
- **Одна вправа двічі в одній сесії** — дозволено, обидва блоки йдуть в історію і рекорди.
- **Редагування завершеної сесії** (цифри, підходи, вправи) — дозволено; рекорди перераховуються, backlog оновлюється сам (він похідний). Видалення сесії — м'яке, з тим самим перерахунком.
- **Зміна шаблону програми** не чіпає старі сесії (в них знімок цілей). Вправа, яку прибрали з шаблону, лишається в backlog, поки її не зроблять, не приберуть або вона не застаріє.
- **Зміна активної програми** → запитати «Очистити пропущені зі старої програми?» (так = створити dismissals).
- **Валідація підходу:** не можна позначити виконаним без обов'язкових полів для типу (повтори ≥ 1; вага ≥ 0 для вагових; час > 0 для `duration`).
- **Сесія через північ** — дата тренування = дата `startedAt` у локальному часі.
- **Швидкодія:** індекси на `exerciseId`, `sessionId`, `finishedAt`. Backlog рахується лише по сесіях за останні 2 × `BACKLOG_EXPIRY_DAYS` днів. Ціль — відкриття екрана < 100 мс на річній історії.
