# Setory — трекер силових тренувань (Expo, TypeScript, офлайн)

Що будуємо і навіщо — `SPEC.md`. Технічні рішення — `docs/ARCHITECTURE.md`. Загальні правила Expo — @AGENTS.md.

## Команди

- `npm run check` — typecheck + lint + тести. Запускати після кожної серії змін; задача не готова, поки він не зелений.
- `npm test -- <шлях>` — один тестовий файл.
- `npm run db:generate` — нова міграція після зміни `src/db/schema.ts`.
- `EXPO_OFFLINE=1 npx expo install <пакет>` — додати Expo-пакет (у хмарному середовищі API Expo недоступне).

## Структура

- `src/app/` — екрани (Expo Router). Тонкі: без SQL і без правил ТЗ.
- `src/domain/` — уся логіка ТЗ, чисті функції + `*.test.ts` поруч. Не імпортує нічого з React Native, `src/db` чи UI.
- `src/data/` — єдине місце з запитами Drizzle. Приймає `Db` з `src/db/types.ts`.
- `src/services/` — сценарії для екранів: data → domain → data. Приймають `Deps` (`deps.ts`); на телефоні — `appDeps`, у тестах — `createTestDeps()`. Помилки для користувача — `UserError` з українським текстом.
- `src/db/` — схема, клієнт, seed. `drizzle/` — згенеровані міграції.
- `src/config.ts` — усі константи з ТЗ.

## Правила даних

- Історія належить вправі (`exercise_id`), а не програмі. Рекорди, «минулого разу», пропущені — рахуються з журналу, не зберігаються.
- ID — UUID на клієнті. Вага — кг (`REAL`), час — мс UTC. Видалення лише м'яке (`deleted_at`).
- Схему міняємо тільки новою міграцією. Старі файли в `drizzle/` не редагуються.
- id вбудованих вправ у `src/db/seed/exercises.ts` ніколи не змінюються. Змінив каталог → збільш `SEED_VERSION`.
- Назви: «Папка» = `Folder`, «Програма» = `Routine` (див. таблицю в ARCHITECTURE.md).

## Тести

- Доменні функції: спершу тест зі сценарієм ТЗ (розділ 12), потім код.
- Код, що працює з БД, тестується на справжній SQLite: `createTestDb()` з `src/db/test-db.ts` (файл з `@jest-environment node`).

## Скіли

Перевірені скіли в `.claude/skills/` (джерела і перевірка — `.claude/skills/README.md`). Перед роботою над екранами читай `expo-router` і `expo-native-ui`, над списками й продуктивністю — `react-native-best-practices`, над тестами екранів — `react-native-testing`. Нові готові скіли ставимо лише після такої ж перевірки.

## Робота

- Одна задача — один етап або одна фича. Спершу план, потім код, потім `npm run check`, потім коміт.
- Не додавай залежності й не міняй правила ТЗ без згоди. Неоднозначне правило — питання до реалізації.
- Тексти інтерфейсу українською, назви в коді англійською.
- Лише бібліотеки, що працюють в Expo Go (тестуємо на iPhone без збірки).
- Нічого з Hevy: ні коду, ні текстів, ні іконок, ні назви. Код з GPL/AGPL-проєктів не копіюємо.
